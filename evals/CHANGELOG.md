# Evaluation changelog

Each entry records the finding, production or harness change, measured effect, and
the exact evaluation configuration. Percentages are deterministic point estimates;
one trial therefore has a degenerate confidence interval.

## 2026-08-05 — DDL snapshot parity

- **Finding:** DDL snapshots omitted inline foreign keys, interpreted `GENERATED BY
  DEFAULT AS IDENTITY` as a default expression, and discarded earlier views when a
  later PostgreSQL statement was unsupported by sqlglot.
- **Change:** Parse column-level `REFERENCES`, derive PostgreSQL's default FK name,
  distinguish identity syntax from a real default, and parse candidate view
  statements independently.
- **Measured effect:** `add_order_notes_table` simulator fidelity increased from
  **47.857% to 49.110%** under the field-level scorer. The inline FK fixture changed
  from **0/1 to 1/1** captured constraints and the mixed-DDL view fixture from
  **0/1 to 1/1** captured views.
- **Config:** `rules_only`, 60-task suite, 1 trial, PostgreSQL committed truth,
  temperature n/a, $0.00 cost; before predictions from commit `8f12189`, after the
  DDL-capture changes, both rescored with the Phase 6 field-level fidelity scorer.

## 2026-08-05 — Sandbox dependency context

- **Finding:** `MigrationSandbox._assemble_context()` used only FK edges, even
  though view, trigger, and SQL column-lineage extractors already existed. Column
  changes behind views therefore reported zero downstream impact.
- **Change:** Assemble all deterministic edge sources, resolve unqualified columns
  when a query has exactly one source table, retain downstream object identities in
  `PredictedChange`, and normalize those identities in the eval adapter.
- **Measured effect:** aggregate blast-radius recall increased from **0.0% to
  21.7%** and precision from **0.0% to 76.9%** at the dependency-context checkpoint.
  The unit case `users.email -> user_emails.email` changed from **0 to 1** reported
  downstream objects.
- **Config:** `rules_only`, 60-task suite, 1 trial, PostgreSQL committed truth,
  temperature n/a, $0.00 cost; `python -m evals.run --adapter rules_only --suite all
  --trials 1 --force`.

## 2026-08-05 — AlterApplier fidelity coverage

- **Finding:** the simulator reconstructed added columns from type alone, modeled a
  rename as drop-plus-add, emitted incomplete FKs, skipped multi-action FK ALTERs,
  and ignored standalone index creation/removal.
- **Change:** Preserve added-column nullability/defaults, rename columns in place,
  apply exact FK fields and actions (including sqlglot `Command` fallbacks), and
  support `CREATE [UNIQUE] INDEX` plus `DROP INDEX`.
- **Measured effect:** simulator fidelity increased from **49.916% to 53.853%**.
  Risk exact match increased from **60.0% to 61.8%**, and non-underestimation from
  **63.6% to 65.5%**. `subtle_fk_action_change` fidelity increased from **52.239% to
  56.322%**.
- **Config:** `rules_only`, 60-task suite, 1 trial, PostgreSQL committed truth,
  temperature n/a, $0.00 cost; same command as above, before and after scored with
  identical Phase 6 scorer code.

## 2026-08-05 — Field-level fidelity scoring

- **Finding:** non-table objects were serialized into one all-or-nothing fact. A
  semantically matching view name with formatting-only definition differences got
  no partial credit, contrary to the plan's field-by-field definition.
- **Change:** Flatten views, triggers, sequences, enums, functions, policies, and
  materialized views into independently comparable field facts while continuing to
  ignore transient sequence and population state.
- **Measured effect:** the regression fixture with a matching view identity/name and
  a differently qualified definition scores **50.0% instead of 0.0%**. Historical
  predictions were rescored with the new metric before production deltas were
  calculated, preventing a scorer change from being presented as a product gain.
- **Config:** deterministic unit fixture plus the same 60-task `rules_only` run;
  scorer version is the code in this Phase 6 branch.
